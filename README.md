# SimpleBoard

Spring Boot 기반으로 만든 SSR(Server Side Rendering) 게시판 프로젝트입니다.  
프론트엔드 프레임워크를 별도로 사용하지 않고, 서버가 HTML을 렌더링하여 사용자에게 페이지를 보여주는 방식으로 구현했습니다.

배포 URL: https://www.simple-board.site

이 프로젝트는 단순히 게시판 기능을 구현하는 것에 그치지 않고,  
백엔드 웹 애플리케이션이 실제로 어떻게 동작하는지 이해하고,  
Docker를 이용한 개발 환경 구성, AWS EC2 배포, 도메인 연결, HTTPS 적용, Nginx 리버스 프록시 설정, 보안 설정, 자동 실행, CI/CD 개념 이해까지 단계적으로 학습하기 위해 진행한 프로젝트입니다.

---

## 1. 프로젝트 소개

SimpleBoard는 회원 인증과 게시글 관리 기능이 포함된 게시판 웹 애플리케이션입니다.  
이 프로젝트를 통해 다음과 같은 흐름을 직접 경험하고 학습했습니다.

- 웹 애플리케이션의 기본 구조 이해
- 정적 페이지와 동적 페이지의 차이 이해
- HTTP 요청/응답 구조 이해
- Spring Boot 애플리케이션 구성
- Spring MVC 기반 SSR 방식 개발
- Thymeleaf를 활용한 서버 렌더링 화면 구성
- PostgreSQL 데이터베이스 연동
- Spring Data JPA를 활용한 데이터 접근
- Spring Security를 활용한 인증/인가 처리
- Docker / Docker Compose 기반 실행 환경 구성
- AWS EC2 서버 배포
- 도메인 연결
- HTTPS 적용
- Nginx 설정
- 서버 보안 강화
- 재부팅 후 자동 실행 설정
- CI/CD 개념 학습 및 GitHub Actions 배포 환경 점검

즉, “로컬에서 돌아가는 웹 애플리케이션”을 넘어,  
“실제로 인터넷에서 접속 가능한 서비스”로 만들어보는 전체 과정을 학습한 프로젝트입니다.

## 5. 이 프로젝트에서 공부한 내용

이 프로젝트는 단순히 기능만 만든 것이 아니라,  
웹 백엔드 개발자로서 꼭 알아야 할 기초 개념부터 배포까지 직접 학습한 과정이 담겨 있습니다.

### 5-1. 웹의 기본 동작 원리 학습
프로젝트를 진행하면서 먼저 웹 애플리케이션이 어떻게 동작하는지 공부했습니다.

- 정적 페이지와 동적 페이지의 차이
- 브라우저와 서버의 역할
- 데이터베이스를 서버 뒤에 두는 이유
- 브라우저 → 컨트롤러 → 서비스 → 리포지토리 → DB → 응답으로 이어지는 흐름
- 서버 사이드 렌더링(SSR)의 개념

### 5-2. HTTP 기초 학습
다음과 같은 HTTP 개념을 학습했습니다.

- HTTP의 역할
- 요청(Request)과 응답(Response)
- 헤더와 바디
- 상태 코드의 의미
- 브라우저와 서버가 HTTP로 통신하는 방식
- GET과 POST의 차이
- 조회와 변경 요청의 차이

이 과정을 통해 웹 애플리케이션이 결국 HTTP 위에서 동작한다는 점을 이해했습니다.

### 5-3. Spring Boot 기반 게시판 애플리케이션 구현
이 프로젝트의 핵심 애플리케이션을 직접 만들면서 다음을 학습했습니다.

- Spring Boot 프로젝트 초기 세팅
- 계층형 구조(Controller / Service / Repository)
- JPA 엔티티 설계
- DB와 애플리케이션 연결
- 폼 처리
- 검증 흐름 이해
- 로그인/인증 처리
- 게시판 CRUD 구현
- 댓글, 검색, 페이징 기능 추가
- Thymeleaf를 활용한 화면 렌더링

### 5-4. SSR 방식 이해
처음부터 프론트엔드 프레임워크를 사용하는 방식이 아니라,  
Spring MVC + Thymeleaf 기반 SSR 구조를 사용하면서 다음을 익혔습니다.

- 서버가 HTML을 만들어 반환하는 방식
- 컨트롤러가 모델 데이터를 뷰에 전달하는 방식
- 템플릿 엔진을 통한 동적 페이지 생성
- 백엔드 중심 웹 개발 흐름

## 7. Docker와 데이터베이스 구성

애플리케이션과 데이터베이스를 보다 일관된 환경에서 실행하기 위해 Docker를 사용했습니다.

### 학습 및 진행한 내용
- Docker의 기본 개념 이해
- Docker Compose를 이용한 PostgreSQL 실행
- Spring Boot 애플리케이션과 PostgreSQL 연결
- 컨테이너 기반 개발 환경 구성
- 서버에서도 Docker를 사용해 앱 실행

### 문제 해결 경험
프로젝트 진행 중 Docker 관련 오류도 직접 겪고 해결했습니다.

- Docker 서비스가 정상적으로 시작되지 않는 문제
- Ubuntu 서버에서 Docker 설치/재설치 과정
- APT 저장소 설정 충돌 문제  
  (`Signed-By` 충돌 관련 오류 경험)

이 과정에서 “문제가 생겼을 때 로그를 보고 원인을 파악하는 경험”을 할 수 있었습니다.

- 가비아 DNS 설정

- Nginx 설정
- HTTPS 적용
- 80 포트 개방

즉, 단순히 앱을 띄우는 것을 넘어,  
사용자가 신뢰할 수 있는 주소와 보안 연결을 갖춘 웹 서비스 형태로 한 단계 확장했습니다.

프로젝트 진행 중 CI/CD 개념도 함께 학습했습니다.

### 학습한 내용
- CI/CD가 무엇인지
- 왜 배포 자동화가 필요한지
- GitHub Actions와 서버 배포의 연결 방식

### 실제로 점검한 내용

- GitHub Secrets 내 `EC2_HOST` 값 변경
- SSH 키 기반 배포 흐름 이해

즉, 아직 단순 수동 배포 단계만 경험한 것이 아니라,  
배포 자동화로 확장될 수 있는 기반 개념까지 학습했습니다.

- 고정 IP(Elastic IP) 연결을 검토
- 운영 환경에서 IP 안정성이 왜 중요한지 학습

### 스왑 메모리 설정

- 리눅스에서 메모리 관리가 어떤 식으로 이루어지는지 간접적으로 학습

### SSH 키 관리
- `.pem` 키 파일의 용도 이해
- `.ssh` 관련 파일 중 어떤 것이 필요한지 구분
- 배포/접속에 필요한 키와 불필요한 파일을 구분하는 감각 학습

이런 경험들은 단순한 백엔드 코드 작성보다 한 단계 넓은 관점에서  
“서비스를 운영하는 개발자”의 시각을 익히는 데 도움이 되었습니다.

## 13. 이 프로젝트를 통해 얻은 것

이 프로젝트를 통해 단순히 게시판을 하나 만든 것이 아니라,  
웹 서비스가 만들어지고 배포되고 운영되는 전반적인 흐름을 처음부터 끝까지 경험했습니다.

특히 다음을 직접 체감했습니다.

- 로컬에서 잘 돌아가는 것과 실제 서버에서 잘 돌아가는 것은 다르다.
- 웹 개발은 코드만이 아니라 네트워크, 보안, 운영 환경 이해도 중요하다.
- 에러를 만났을 때 로그를 보고 원인을 좁혀가는 과정이 매우 중요하다.
- 도메인, HTTPS, Nginx, Docker, EC2 같은 요소들이 실제 서비스에서 어떻게 연결되는지 알게 된다.
- “작동하는 결과물”을 인터넷에 올려보는 경험은 큰 자신감을 준다.
